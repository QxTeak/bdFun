# 弱网播放回跳修复与静态审计

## 原因与处理

网络加载失败会触发原始地址/兼容地址回退。旧 BindPlayerSource 每次重建源都传页面初始 resumePositionMs，Media3 setMediaSource 默认重置位置；播放到缓冲尾端发生 IO 错误后，因此可能跳回 0 或最初的历史位置。

现在用 bvid:cid 标记同一内容，适配器在替换媒体源前读取实时 position/playWhenReady/speed，一次性提交起始位置。同内容切画质和多次回退同样保留位置；不同分 P、视频和未标记的后台队列仍遵循入口位置。没有用 max(旧位置, 新位置)，因此用户手动回拖到 0 仍有效。

流式内存缓冲低水位 15→45 秒，上限保持 120 秒；首次起播保持 1 秒，耗尽后的再缓冲 2→5 秒。网络连接/读取超时显式为 15/30 秒。沿用 Media3 的加载重试，不增加无限重试；不引入磁盘副本或更改离线缓存格式。代价是可能增加流量、内存占用和卡顿后的等待时间。

## 静态检查范围

- 详情：唯一换源入口已携带 bvid/cid，源重建不再复用初始位置；显式 seek 只用于用户操作、跳过片段和真正 Ended 后的循环。
- 后台：移交仍持有同一控制器，无新播放器副本。独立后台队列 prepare 是切换新条目，故意不继承上一条位置。
- 内嵌预览：prepare 用于新媒体加载，无错误回调切源链；保留其独立默认缓冲与循环行为。
- 直播：新直播地址按直播入口加载，不套用点播恢复位置。
- 离线缓存：本地 URI 通过同一详情入口播放，保持文件、目录、JSON 与传输实现不变。
- 结束状态：缓冲/Idle 不产生 Ended；既有结束确认逻辑和循环 seekTo(0) 不改。

## 验证

纯 JVM 回归覆盖缓冲耗尽错误位置、暂停换画质、倍速、重复恢复、主动回拖到 0、新视频/分 P、首次加载与未标记后台条目。执行 core:application:test、app:testDebugUnitTest、danmaku-engine:test、app:assembleDebug。

待设备手动检查：播放至非零位置→限速/断网直至缓冲耗尽→恢复网络；切清晰度→切分 P→全屏旋转→画中画→后台播放→退出→重新进入恢复进度。检查暂停状态和倍速；模拟 CDN 出错后原始/兼容地址回退。本机当前无 adb 设备，不能将静态与 JVM 验证视为上述实机检查已通过。

## 详情顶栏与遮罩追加修复

横屏详情顶栏保留 ProgressiveTopBarMaterial 的顶部渐进模糊；竖屏仅向 Tab 和弹幕胶囊提供随页面滚动的 280ms 材质进度。横竖屏共用同一进度：0 时使用与合集框相同的 groupedBackground 不透明底色，滚动后渐显玻璃；控件仍在页面采样树外。移除播放器底边的渐变，页面底部渐变只在评论 tab 显示，简介/推荐没有渐进遮罩。播放器内部的操作控件明暗遮罩不属于页面遮罩，保持原行为。

追加验证：debug 构建通过；模拟器真实视频详情已启动并查看竖屏平面控件和简介边缘。横屏自动进入全屏影响双栏验证，横屏双栏与明暗主题的完整人工对照仍需补充。
