# 推荐算法优化 v1 实现与验证

日期：2026-11-14；PR #52。用户要求方案与实现在同一 PR，原“每阶段独立 PR”流程以此为准。算法为本地实验能力，默认关闭；本记录不宣称已经复现官方或取得质量提升。

## 已接入的实际行为

- 设置 → 首页推荐 → **推荐算法优化**；新安装和旧安装缺失文件均关闭，独立保存，不增加旧 SettingsStore 字段、不修改 recommendWeb 来源选择。
- 开启：未来请求批次在既有排除后执行去重、官方名次先验、长期/会话观看偏好、曝光/已观看降权及 UP/分类多样性；最大位移三位、稳定同分、候选不足保留内容。已发布列表不重排。
- 关闭：停止新增优化曝光/点击/观看写入，恢复原分页阈值与无优化排序；保留历史学习。旧优化 ticket 失效，下一次成功刷新重建基线列表，刷新失败保留现有内容。
- 清除推荐学习记录：仅清当前账号的本机聚合记录和会话，开关不变；关闭时也可清除。旧 ticket 无法写回，不删除官方历史/收藏/关注或播放进度。
- 首页处于当前稳定 tab、搜索关闭、无卡片操作弹层且窗口有焦点时，卡片可见高度至少 50% 连续 800ms 才算曝光；重组/旋转不会重复提交相同会话内 BV。预取和卡片组合不算曝光。
- 首页点击才建立学习归因；共享 PlaybackSessionStateHolder 的播放快照按单调时钟采样。暂停/缓冲不计时，seek 不计跳过区间，重复区间合并，倍速区分内容和墙钟时长。不足五秒不算正向观看；长视频允许累计有效观看达到五分钟形成正向反馈，后台贡献减半。以上为实验初值，不是已标定的满意度模型。
- 长期和会话偏好分别使用 14 天/30 分钟半衰期，以不同 BV 为证据并向零收缩；单视频反馈取最大值，避免循环放大。曝光不会刷新旧观看证据的时间。
- 开启时约两屏预取；重复/过滤后无新增最多额外请求两批，预算耗尽提示手动继续，不伪造推荐结束。关闭仍保留原请求数量和结束规则。
- 初始化/写入在 IO 调度器，排序在 Default 调度器；后台轮询不触碰播放器操作。排序异常回退本批原序；取消必须继续传播。

## 存储与并发

v1 使用按 BV 聚合记录，而非完整原始事件日志；保存曝光/点击时间和满意观看证据。单文件 recommendation/recommendation_v1.json，格式 version=1，临时文件写入并 fsync 后原子替换；未知版本忽略、损坏/超预算向设置页报告错误。

账号键为本地 SHA-256 派生键；游客只保留内存，不迁移到登录账号。账号 revision、优化 generation 共同组成 ticket，在事件提交与请求结果提交时核验；清除/关闭后即使未及时收到页面投影也拒绝旧结果。写入管道串行并合并完整不可变快照，旧写入不能排在清除快照之后。

实际 v1 预算比方案更小：全账号合计最多 5000 个视频记录、加载/更新时逻辑淘汰闲置 30 天记录，下一次写入移除磁盘旧记录、单个快照 4MiB 上限（原子替换临时双份峰值 8MiB）；游客最多 5000 个记录、会话兴趣最多 300 个 BV、待归因点击最多 20 项。没有原始事件上传或新的服务端曝光上报。完整事件重放/互动撤销尚未实现，不将聚合记录宣称为完整事件系统。

## 阶段状态和范围差异

| 阶段 | v1 状态 | 尚待验证/实现 |
|---|---|---|
| REC-00 | 设计与入口完成，按当前实现修订范围 | 质量参数随评估迭代 |
| REC-01 | 保留当前 Web/App 协议、凭据、字段和兜底行为，无新增接口推测 | 同账号真实响应脱敏样本、分页语义与官方对照，不宣称完成协议审计 |
| REC-02 | 默认关闭开关、清除、账号隔离、有界本地聚合存储、旧事件守卫接入 | 完整事件 ID/曝光 ID、原始事件重放与互动撤销不是本版能力 |
| REC-03 | 新批次轻重排、多样性、两屏触发和有限补位接入 | 120 候选为单次排序上限；尚无三批缓冲池、600 条列表锚点淘汰或新内容数量提示 |
| REC-04 | 首页点击关联的观看学习、衰减、置信度和有界兴趣重排接入 | 点赞/投币/收藏/关注的独立证据与撤销、快速返回负反馈、分 P 区间归属、登录后旋转/画中画/后台完整回归 |
| REC-05 | 未启用探索与实验分组 | 无评估样本前不引入探索扰动；真人质量实验、设备性能门槛仍待验收 |

上述范围差异明确保留后续工作；不把“已有可用本地算法”写成所有 REC 阶段完成。v1 不新增模型或依赖、不跨来源混分、不逐条拉详情补画像特征、不自动开启实验。
