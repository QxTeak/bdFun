# BUF-70 点播缓冲策略

对应 issue #70。开关默认关闭：关闭使用分阶段固定规则，开启使用本地观看生存统计。
两者共享 VideoBufferProvider(CacheStrategy)，输出 shouldLoad、targetMediaMs、lowWaterMediaMs、additionalMediaMs。
这些是媒体时间预算，不是 HTTP 字节承诺；ProgressiveMediaSource 的请求边界和音视频合并仍由 Media3 决定。

## 边界

core/domain/buffering 为纯 Kotlin 模型、策略、会话状态和存储端口；infra/storage 保存版本化聚合；
infra/playback/StrategyLoadControl 执行决策，AppContainer 注入账号与设置。上层页面不识别策略类型。
设置复用播放设置控制器、逐字段投影与索引渲染器，无新增 UI 控件或依赖。
直播、信息流预览、离线下载不使用此策略；详情点播与同实例的后台/画中画共享。

## 固定规则与共同保护

实际播放不足8秒目标8秒，8–30秒目标20秒，之后35秒；低水位为目标的40%。
上述均为墙钟播放秒，按当前倍速换算为媒体时间；单次目标最多120媒体秒。
曾发生重新缓冲时目标至少25墙钟秒、低水位至少10秒。低水位开始、高水位停止，中间保持原状态。
暂停只允许补足约1墙钟秒；最大64MiB allocator预算，实际请求/解复用可能有超调，并非整进程内存上限。
首次起播1墙钟秒，卡顿恢复3秒；达到字节上限允许起播避免死锁。尾部就绪由Media3处理。
不人为限速、不建额外下载器或测速循环、不改变清晰度、音频焦点或解码设置。

## 学习 v1

6档曝光时间：0–3/3–8/8–15/15–30/30–60/60+ 秒；计量实际播放墙钟时间，倍速和seek不增加观看时长。
每档曝光秒数和主动退出计数，指数风险率采用2事件/60秒先验；生存概率为各相交区间风险积分的负指数。
每完成会话旧统计乘0.98衰减；样本量/30控制学习强度，冷启动等于固定规则。
生存概率只调整固定预算倍率，最终目标限制6–45秒，安全保护在两种策略之后统一执行。
不完整样本只贡献曝光：自然结束、卡顿、错误不会记录主动退出。崩溃未结束会话不写入。
同mediaKey换清晰度/网络重试保留会话；新key或release结算。后台交接不release则不结算。
账号或开关变更丢弃当前未提交部分，之后的片段按不完整样本处理；关闭不读/更新历史。
账号各自持久化13个数值，游客仅进程内存；不上传、不保存BV/标题/原始轨迹。关闭不删除既有聚合。

v1不按入口/视频类型再分桶，也不训练清晰度策略；模型是受约束的本地估计，不保证节流/功耗收益。
不完整曝光仍可能受网络条件选择偏差影响，应通过真实数据验证后再细化归因。

### 初始化闪退修复

首版给DefaultLoadControl父类传minBufferMs=1000、rebuffer=3000，违反其构造约束，
即使覆盖shouldContinueLoading也会在创建时抛IllegalArgumentException；两种模式均受影响。
修复为minBufferMs=3000，实际两种策略仍由覆盖方法控制，不改变首次起播1000ms。
新增infra/playback的Robolectric测试直接实例化真实Media3 LoadControl，两种模式修复前均复现该异常；
CI在签名之前执行这组测试。复用版本目录已有JUnit/Robolectric，只有测试依赖；
纯策略测试无法覆盖Media3构造断言，Android stub返回默认值也不能替代真实运行时测试。

### Home/锁屏保活与 PR81 整合

整合PR81的WAKE_MODE_NETWORK与WAKE_LOCK权限。此前只有退出页面交给唱片的adopt路径启动播放前台服务；
Home/锁屏保留Activity时未启动。现在VideoActivity.onPause在仍可见时按后台开关、活跃会话、playWhenReady启动服务，
不能用isPlaying判定，否则正在缓冲的会话会丢失保活。onResume撤销非detached服务，clearState清理服务；
后台唱片仍沿用原adopt和退出路径。网络锁随Media3实际播放状态持有/释放；不申请电池优化豁免、不永久持锁。
这修复了已确认的生命周期缺口，不宣称已经证明用户后台断流的唯一原因。
仍需真机Wi-Fi/蜂窝分别测Home与锁屏超过最大缓冲时长、暂停/恢复、画中画、返回原页及退出清理。
