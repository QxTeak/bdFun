# 评论 AI 人格屏蔽的来源与边界

## 上游

| 项 | 值 |
|---|---|
| 仓库 | [ybyz2/bilibili-dafeiyu-blocker](https://github.com/ybyz2/bilibili-dafeiyu-blocker) |
| 引用提交 | `e19566e384eef5996ad0dccf66e0c706520832eb`（v1.6.1，2026-11-16） |
| 许可 | MIT（全文见上游 `LICENSE`） |

## 取用了什么

只取判定内核（上游 L0 `Pure.isBlocked` 与其正则表），落在
`core/domain/.../CommentAiBlockPolicy.kt`：

| 规则 | 上游写法 | bdFun |
|---|---|---|
| 账号名含「肥鱼」 | `RE_NAME`，只看名字、优先级最高 | 同名常量，`CommentItem.uname` |
| 品牌词 | `大肥鱼 肥鱼 鲸鱼 大肥鲸 鲸鱼娘 本鲸 本鱼 本肥鱼 主人` | 同表 |
| 单字 | `鱼 鲸`（杀戮档） | 同表 |
| 全角标点 | `[：；「」]`、`[\u2014\u2015\u2500]`、`--` | 同表 |
| 真 @ 到人 | `RE_AT` 要求 `@` 前不是 `\w.+-`、后跟人名类字符 | 同表，`12345@qq.com` 不算 |
| 自动引用前缀 | `^回复\s*@[\s\S]{0,40}?\s*[:：]\s*`，判 @ 前剥掉 | 同表 |
| 简繁通吃 | 不转换文本，把字扩成字符类 `鱼 → [鱼魚]` | 同表，只收 `鱼/鲸` 两对 |
| 档位 | `cup / standard / kill / atonly` | 常量 1/2/3/4，语义逐档对齐 |
| 楼中楼 | `only / whole / none` + 主楼命中整楼删 | 常量 0/1/2 |
| 置顶 | 置顶评论一律保留 | `CommentItem.isTop` 跳过判定 |

判定顺序也照抄：账号名 → 品牌词 → @ → 单字 → 全角标点，档位把顺序切段。

## 没有接入什么

| 上游能力 | 原因 |
|---|---|
| 删除评论 / 拉黑用户（`delReply`、`batchBlock`、`-509` 退避、`-352` 停止） | 属于账号写操作，误伤不可逆；本轮只做「不显示」 |
| 「已清 N 条」计数、删除/拉黑横幅 | 需要自己的 UI 与账本，和过滤是两件事 |
| 评论池（20000 条环形缓冲）、账本（20000/3000）、候选集 | 只服务删除/拉黑 |
| 自定义屏蔽词 / 屏蔽用户名 | 需要二级编辑页面，留给后续任务；策略层暂不含自定义词 |
| fetch/XHR 拦截、Shadow DOM 面板、Settings 存储 | 浏览器专属 |

## 与上游的行为差异

1. **不删数据源，只过滤列表。** 上游改写接口 JSON，评论不会进渲染队列；bdFun 在
   `CommentListStateHolder.fetch` 里过滤仓库返回的 `CommentPage`，属于展示层过滤，
   `total`（acount）仍是服务端原值。
2. **整页被屏蔽时继续往后取 3 页。** 上游把 `cursor.is_end` 标真了事，博主评论区全是
   AI 评论时会看到空白；bdFun 先补取，避免首屏空白。
3. **楼中楼计数按实际摘掉的预览条数减 `replyCount`**，与上游 `rcount -= hit` 同一口径。
4. **默认关闭。** 上游装了就生效；bdFun 是客户端功能，未主动开启前必须和上一版一致。

## 修改注意事项

- 新增判定词要先想清楚会不会误伤：`主人` 属于品牌词表，标准档就会命中，误伤面已经不小。
  杀戮档（单字「鱼」+ 全角标点）只适合极端场景，不要在默认值里打开。
- 改 `strength` / `replyMode` 常量时同步 `settings-index.json` 的 `options`，否则设置页
  选到的值和策略对不上。
- `CommentAiBlockPolicy` 的判定正则必须是纯 JVM 可跑的，不要引入 Android / JSON 依赖。
