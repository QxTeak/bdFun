# 弹幕交互对齐与 BiliPai 移植评估

对照源码：BiliPai [7a8cebf](https://github.com/jay3-yy/BiliPai/tree/7a8cebf95fad712e60184e855575161599d591db) 的 `HotDanmakuBar`、`HotDanmakuPolicy`、`DanmakuManager`、`DanmakuRepository`、`DanmakuActionToolbar`，以及 Hyper-PiliPlus [0d08dd2](https://github.com/AritxOnly/Hyper-PiliPlus/tree/0d08dd25bdeaa9a55e5a0e333154b681fd8048fe) 的 `header_control.dart`、`danmaku.dart`。

- 高赞候选使用过滤后的弹幕。最近 15 秒、分段点赞数至少 10 是候选规则。按文字、计数和两个按钮的实际宽度选择最多三条完整内容。整行仍容不下的条目跳过。
- 浮层高度来自实际布局。渲染器保留原轨道和时钟，入场时给高赞栏留位，已在重叠区的弹幕在绘制时裁掉，高赞栏已展示的条目按 ID 和正文去重。
- 热门栏和普通弹幕操作共享统计。分段 `like` 用于候选排序及缺失数据时的显示。统计接口 `likes` 是总点赞数，`user_like` 是账号是否点赞。分段 `count` 仍表示服务端合并重复数。更新后重读统计，失败回滚，已有赞和已取消按上游返回码纠正。
- 高赞栏可直接切换点赞或确认跟发。普通弹幕选中后固定，点赞时浮层保持打开并更新计数，复制、举报和释放策略沿用播放器入口。

## 是否直接移植

可移植，建议把高赞栏、操作工具条、统计仓储和对应测试按功能搬入 bdFun 的现有分层。仓库已经有由 BiliPai 移植的 Apache-2.0 渲染引擎及隐藏条目、顶部让位、单条捕获接口。新版 BiliPai 的完整弹幕功能另外依赖播放器视口、Media3、设置流、分段调度及命令弹幕。整包替换需要重接这些宿主契约，风险集中在旋转、切 P、画中画和状态恢复。本轮按播放器业务入口增量接入，具体验证范围见下。

代码许可的基础条件清楚：两边应用都按 GPLv3 发布，BiliPai 的渲染引擎模块单列 Apache-2.0。复制应用代码时保留版权和许可证、标明修改和日期，并在交付 APK 时提供该 APK 对应源码。逐文件核对第三方声明。商标、品牌、截图和资源权利独立于代码许可，未经核对的资源不宜随模块搬入。保留 bdFun 品牌并在出处文档中固定上游版本、列出移植范围，能减少归属争议。

## 播放器业务对齐清单

| 入口 | 已接入的业务 |
| --- | --- |
| 普通、高赞弹幕 | 播放中选中固定、关闭恢复，点赞／取消，服务端真实计数，复制、同款跟发、举报 |
| 弹幕池 | 当前已加载弹幕计数、搜索、按时间／点赞排序、跳到出现时间或正文时间链接、查看和操作单条弹幕 |
| 本人弹幕 | 识别发送者及本人，保留发送响应中的弹幕 ID，撤回后从本分 P 的播放和弹幕池中移除 |
| 屏蔽与同步 | 按关键词、正则和作者 hash 屏蔽，增删云端规则，主动上传当前弹幕设置 |
| 命令弹幕 | UP 提示、关联视频、关注及三连入口，提交投票和评分，评分后重读服务端人数及均分 |
| 特殊弹幕 | 逆向轨道，Mode 7 位移／透明度／路径，Mode 9 BAS 文本、基础路径和按钮跳转 |

半屏输入、全屏输入以及在页面内操作弹幕继续使用 bdFun 原有外观。新管理弹层和确认使用 Miuix／TeakUI。播放器仅展示当前已加载的弹幕，列表数量和稿件弹幕总量分别使用各自的来源。

已用只读模拟器安装 Debug APK，打开公开视频，检查高赞快捷操作、播放中普通弹幕选中，以及从“更多”进入操作面板。发送、点赞、举报、撤回、云端配置写入和命令提交仍需有效账号回归。跨分 P、横竖屏及画中画需要继续做端到端验证。本次 BAS 呈现覆盖基本文本、路径和目标跳转，复杂嵌套绘制、完整的远端范围索引，以及大会员渐变和 UP 身份样式发送尚待专项对齐。
